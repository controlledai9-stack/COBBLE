# Response implementation contracts and current verification boundary

Date: 5 November 2026. Branch: `codex/response-containment`.

These are implementation decisions, not a claim that S0 or the full plan is finished. Local tool/broker integration, conservative information-flow controls, generated-artifact/dependency hooks, Docker validation and the quarantine/registry/review/release workflow have evidence. Local health leases and fresh-session recovery now have bounded implementation evidence; independent observation, broader recovery and production identity remain unresolved gates.

## Implemented foundation

1. The server owns `SWARMGUARD_RESPONSE_MODE` (`off`, `monitor`, `enforce`) and `SWARMGUARD_RESPONSE_MINIMUM_GATEWAY`. Persisted profiles cannot silently change on service reconstruction; a future explicit policy migration is required. A protected enforce session requires containment and rejects weaker gateway modes. Protected `/api/simulate` and suite child runs register with the persistent controller before runtime effects.
2. Only a trusted local operator may register stable principals and associate run agent IDs with them. Restrictions attach to the principal and remain effective through newly registered sessions/agent IDs. This is not yet production authenticated task-lineage derivation. Baseline capabilities cannot be granted through resume.
3. Principal revisions serialize restriction/recovery/stop changes. Restrictions are independently linked to incidents; resume must name restrictions and cannot clear another incident. Terminal stop prevents new sessions. Simple resume cannot release clean-context holds. The [local fresh-session recovery adapter](member4-recovery.md) now uses a designated deterministic baseline session, empty memory/broker checks and context-epoch fencing; broader external/LLM recovery remains incomplete.
4. Authorization is advisory until a trusted executor rechecks. Results carry policy epoch, principal revision, expiration, restrictions and `enforcement_verified=false`. Baseline deny wins. Code/shell execution remains sandbox-only; high-impact publication/merge/deploy/secret operations require review and a supported executor. Exact artifact consumption requires a registered identity.
5. Action approval binds the complete canonical request, executor, policy epoch, principal revision and expiration. Admission reserves it once into a durable prepared operation. It is not artifact trust and not an effect receipt. Retry with the same idempotency identity returns the same operation; another operation cannot reuse its reservation.
6. SQLite transactions atomically persist response state, command result and audit append. Idempotency keys are scoped by workspace/caller/action and bound to request digest. Changed payloads conflict. External effects are forbidden inside these callbacks. Local tool, validation, capture, Git release and component invocation now use durable intents. Local registry selection/approval consumption commit atomically; Git crash-gap readback and post-effect holds have focused evidence. Full distributed health/fencing/clock qualification remains pending.
7. Response tables are separate from generic pipeline document replacement. Audit entries are insert-only through SQL triggers, chained by sequence/hash and checked on reopen; a local head tracks the expected tail. This detects the tested corruption conditions, not a host/database administrator rewriting all history. Independent anchoring and incident-specific evidence access remain later work.
8. Version 2 snapshots hash bytes, portable relative paths and Git executable modes. Capture rejects traversal, `.git`, device/path/case/file-directory aliases and size/count violations. Reads reverify frozen bytes. Git intake refuses symlinks/submodules/LFS and materializes immutable blobs without checkout hooks/filters. Quarantine preserves restricted-class snapshots/patches/changeset metadata, validation/review and action identity. The versioned registry has current/previous trusted selection, explicit development mocks and state/context/lineage/revocation checks. Worktrees are not execution references or sandboxes; retention enforcement and generated-bundle capture remain pending.
9. Response reads/writes and sensitive managed legacy pipeline reads/writes require a dedicated bearer operator token of at least 32 characters. Mutation bodies reject extra fields and require idempotency/revision information where applicable. Full viewer/reviewer/executor roles, field-level permissions and denial audit remain pending.
10. Public response APIs cannot upload trusted execution receipts or run commands/host paths. Status reports local virtual-tool integration with aggregate enforcement unverified. The per-run response report distinguishes actual local receipts from simulated events. An authenticated operator UI now handles human decisions, Git linkage/salvage and separate exact-action release; see [operator evidence](member4-operator-ui.md).
11. The Docker JSON worker accepts only a server-selected module/function and bounded JSON arguments against a freshly copied verified artifact. Images are immutable IDs/digests, with no automatic pulls or host fallback. Each test uses a fresh restricted container; expected outputs and assertions stay in the trusted controller. Candidate-written pytest/sitecustomize plugins cannot replace these tests.
12. A separate pinned offline Semgrep image owns the custom rules. Scanner processes parse candidate bytes inside restricted containers, with metrics/version checks disabled and no credentials/network. Candidate ignores and suppression comments cannot hide the tested finding. JSON/SARIF, scanner/rule/image identities and coverage are retained as validation evidence; unscanned files or errors prevent a passing result.
13. Validation records precede Docker effects, allow one active validation per artifact, and persist each operation identity before dispatch. Failed/uncertain work remains reconciliation-required. Expired leases allow daemon-backed teardown and interrupted status; live leases refuse recovery. Current artifact revision/policy must still match at completion. Passing tests without the scanner yield checks-pending, and no validation changes trust, reviews or approvals.
14. Human review binds exact candidate/artifact, contract checks, image/rules, policy, revision and bounded freshness. It is distinct from publication. Local release reserves an exact action approval, rechecks current state, and verifies the selected identity or Git target. Changed destinations require a new combined-result capture/validation. A post-dispatch revoke records the applied effect but holds selection; it never claims cancellation or rollback.
15. Component calls use the reviewed catalog interface and freshly recheck selection/eligibility/principal fences before dispatch in Docker. Requests have bounded JSON and durable idempotent operations. Revocation during execution withholds the result; uncertain execution requires expired-lease teardown. Code eligibility does not grant data/output eligibility. Runtime virtual-tool reports separate these executor scopes rather than counting them as virtual-tool prevention evidence.
16. Simulator dependency calls use server-owned role/contract declarations frozen in session state. Model calls cannot downgrade consumer class, state contract or execution context. Structured and autonomous tools route through the dedicated component executor, recheck selection/dependency state at dispatch/completion, and persist conservative output lineage before agent handoff. See [dependency boundary](member4-simulator-dependencies.md); richer graph/declassification remains unimplemented.
17. Each protected local runtime has one non-transferable observer lease: 30-second expiry, five-second engine heartbeat, durable session/observer binding, process-only renewal secret, wall and monotonic checks, and no self-revival after observed expiry/renewal failure. Current lease state is part of action admission and output handoff, including monitor-mode structural fences. A late effect under changed authority is reported as applied with output held, never as prevented. Engine exit/setup failure closes authority. Public health reads omit owner hashes and explicitly state that this is not independent attestation. See [runtime contract and measurements](member4-runtime-control.md).

## Required runtime and information-flow contracts

The implemented local integration registers sessions before effects, establishes simulator slot identities, maps controlled virtual tools to capabilities, denies unsupported tools, checks current policy/revision/health at action admission and produces local executor receipts. Every additional executor must implement the same boundary protocol and prove its own coverage. Static baseline policy and response restrictions combine conservatively. An event label alone cannot establish a real prevention.

Sensitivity and integrity are separate dimensions. Runtime wrappers now persist conservative principal/resource labels, propagate sensitive context to writes and permitted messages, and hold unauthorized relays or unknown-lineage egress in enforce mode. A model-supplied `data_ref` cannot establish trust. User-task context is conservatively unknown. The full artifact/dependency graph, reviewed declassification and clean-context recovery remain pending.

Git/validator/registry adapters now use durable intents, revision/epoch fences, bounded execution leases, effects outside database transactions, and scoped readback/receipts/reconciliation. The local runtime additionally uses observer leases. Remaining external adapters must prove coverage, cancellation and independent observation before their releases are marked verified. These protocols do not establish distributed host/clock integrity.
